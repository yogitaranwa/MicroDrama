# Reference-to-video route (2026-10-26)

Status: planned and validated only. No reference-to-video request has been
submitted by this project, no generated R2V media exists, and nothing here is
evidence that a model honors references. Live submission still requires the
standard manifest approval; output still requires media review.

## Why this route exists

F22/F23 are project evidence that the single-start-frame prose I2V route
drifts in wardrobe, framing, camera and eyelines even under explicit locked
prompts. The audit's fix direction was explicit reference/state contracts
plus a materially different tested control route. Reference-to-video is that
candidate: each shot request carries named, hash-bound character and location
references instead of relying on one start frame and prose.

## Verified API contract (checked 2026-10-26)

Sources:
- https://docs.magichour.ai/api-reference/video-projects/text-to-video
- https://docs.magichour.ai/api-reference/models
- magic-hour Python SDK request types (registry install, 2026-10-26)
- Vendor usage guide: https://magichour.ai/blog/seedance-20-reference-guide

- `POST /v1/text-to-video` accepts `references`: 1-10 items of
  `{"file_path": "api-assets/...", "name": "..."}`. Names are single tokens
  without `@`; the prompt addresses them as `@name`.
- Reference-capable models and verified rates (credits/second, 720p):
  minimax-h3 48, kling-3.0 48 (audio extra), seedance-2.0-mini 192,
  seedance-2.0 288, seedance-2.5 576, wan-3.0 96. Durations and resolutions
  differ per model; `magicdrama/audiofirst/magichour_catalog.py` carries the
  exact validated table with `VERIFIED_ON`.
- seedance-2.0 is documented for "reference-led clips with precise subject
  control"; minimax-h3 also accepts image, video and audio references at the
  lowest verified rate.
- The vendor guide itself states references condition a result; they do not
  guarantee identical faces, timing or choreography. Treat every R2V clip as
  review-required.

## Scope honesty

- This planner covers shots without visible speech. Shots with visible
  speakers need exact-audio conditioning (audio_to_video / performance
  routes). R2V native audio is not a locked-soundtrack contract, and the
  planner refuses to reclassify speaking shots.
- Model choice is a user/budget decision. `compare_route_quotes` produces
  exact side-by-side catalog quotes for the same shot list; it never picks a
  more expensive model by default.

## Modules

- `magicdrama/audiofirst/magichour_catalog.py` - dated, sourced model
  catalog: durations, resolutions, credit rates, reference kinds, aspect
  ratios. Unverified rates raise instead of guessing.
- `magicdrama/audiofirst/r2v.py` - per-shot named reference selection from
  the hash-bound bank (explicit gaps, never substitution, 10-reference cap),
  prompt composition with `@name` mentions and continuity state, request
  building, episode manifests, and route quote comparison.
- `magicdrama/audiofirst/live.py` - `_validate_r2v_job` enforces the compiled
  binding, catalog shape, verified quote and provider upload paths before any
  live adapter accepts a job.
- `magicdrama/audiofirst/routes.py` - `magichour_r2v_minimax_h3` and
  `magichour_r2v_seedance_2` registered with all capabilities `unverified`.

## Performance detailing (2026-10-26)

User direction: every dialogue line carries its own emotional/performance
detailing; wording is unconstrained. `magicdrama/audiofirst/detailing.py`
validates presence (emotion + delivery required, emphasis/pauses/reaction
optional free text) and maps only a verified tag lexicon into eleven_v3
request text. Unknown wording stays as review guidance; code never invents
bracket tags. Verified text-to-dialogue settings: `stability` (lower =
broader emotional range) and `similarity`; no documented per-line speed
control, so brisk delivery is directed with tags such as [rushed] and
measured against the actual WAV afterward.
